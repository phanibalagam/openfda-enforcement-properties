# Properties of the openFDA drug enforcement export

Code, recorded results and hand-mark records for a manuscript in preparation on what the
openFDA drug enforcement bulk export can and cannot support.

**Status: manuscript in preparation. Not peer-reviewed.** This README will be updated to
match the final manuscript before the v1.0.0 release is cut.

## The data snapshot, and why it is redistributed

```
data/drug-enforcement-0001-of-0001.json.zip
SHA-256  c6eb46526a3ad52102a88b65727874c2e23c43300b27e704eada05960d755092
Bytes    4,004,072
Records  17,975
Source   https://download.open.fda.gov/drug/enforcement/drug-enforcement-0001-of-0001.json.zip
```

The export is a **snapshot, not a history**. Downloading it again on a later date returns a
different file, and the numbers here would not reproduce. The exact snapshot the analysis ran
on is therefore included rather than fetched at run time. It is a United States federal
government work and is in the public domain.

## What is here

Five validation runs, each with its criteria written down before the sample was drawn.
**750 hand marks** in total, recorded as JSON alongside the scripts that drew them.

| Run | Question | Result |
|---|---|---|
| 1 | Is the recall-repeat question feasible on this export? | Stopped on a pre-set floor. `openfda.product_ndc` is present in 18 percent of records (3,236 of 17,975), below the 30 percent coverage floor fixed before the first run on real data |
| 2 | Can National Drug Codes be recovered from `product_description`? | Fail |
| 3 | Is the coverage trend a parser artifact? | No. The trend survives. Parser validated at 95 / 100 / 95 percent precision across three eras with a flat 2.5 / 2.5 / 2.5 percent miss rate |
| 4 | Does a no-NDC-expected label explain the trend? | The explanation does not stand. Era precisions 100 / 97.5 / 77.5 percent; the label misses early records far more often than late ones |
| 5 | Does a second, independently designed label fix it? | No. Label v2 fixed precision, not recall. Miss rates 40.0 / 32.5 / 7.5 percent by era |

Both labels miss early compounded products several times more often than late ones, so
attribution of the coverage trend to a changing product mix **cannot be measured from the text**.
That is reported as attempted and unresolved.

## What is NOT claimed here

- **Run 4's decomposition is not reported anywhere in this repository or the manuscript.** It was
  computed on a label that failed its own pre-registered validation, so it does not support a
  conclusion and is not quoted.
- **Label v2 is not fit for use.** It is described as an attempt that failed, with its numbers. It
  is not used to support any claim.
- Nothing here supports a statement about how often this happens in other datasets. The findings
  describe one file.

## Reproducing

Run the scripts with bytecode writing disabled:

```
python3 -B run2_ndc_recovery.py
python3 -B run3_parser_validation.py
python3 -B run4_label_validation.py
python3 -B run5_label_v2.py
```

Each writes its own `runN_results.json`. Hand marks are in `runN_marks.json` and are inputs, not
outputs: they were made by hand and are not regenerated by the scripts.

`RUN5-RULES-PRESAMPLE.md` is the label v2 rule text exactly as it stood **before** any run 5
sample was drawn.
